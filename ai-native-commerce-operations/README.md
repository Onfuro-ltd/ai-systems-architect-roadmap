# Domain 27 — AI-Native Commerce and Operations

## Learning objectives

By the end of this domain, you should be able to:

- explain the core concepts and distinctions across AI-native commerce/operations architecture, catalogue, pricing, inventory, marketing, support, finance and controlled business actions.
- build or evaluate a representative implementation rather than relying on a demo;
- make architecture decisions that account for reliability, security, cost, scale and operations;
- define the evidence, evaluation and governance required before production adoption.

## Purpose

Commerce and operations provide a practical domain for integrating data, forecasting, decision intelligence, automation, agents and human control.

This domain uses generic commerce architecture. It is not an implementation blueprint for any particular company.

> AI-native commerce is not a collection of marketplace chatbots. It is an operational system that connects authoritative commercial state to evidence-backed decisions, controlled actions and measurable outcomes.

## Core architecture

```text
Commerce systems + channels
          ↓
Canonical operational data
          ↓
Events + reconciled state
          ↓
Domain intelligence
 catalogue / demand / pricing / ads / service / finance
          ↓
Decision intelligence
          ↓
Policy + permissions + approvals
          ↓
Durable workflows + typed tools
          ↓
Channels / systems of action
          ↓
Verified commercial outcomes
          ↓
Evaluation + feedback
```

## Principles

1. Reconcile operational facts before reasoning over them.
2. Keep channel-specific complexity behind canonical contracts.
3. Separate forecasts from decisions.
4. Optimize contribution and outcomes, not vanity metrics.
5. Treat inventory, pricing and advertising as coupled systems.
6. Preserve tax/financial calculations in deterministic controls.
7. Verify marketplace actions after execution.
8. Use human approval according to consequence and uncertainty.
9. Learn from realized commercial outcomes.
10. Keep the architecture portable across channels and models.

## Takeaway

> Commerce becomes AI-native when intelligence is embedded in the operating loop while authoritative state, policy and financial control remain deterministic.
