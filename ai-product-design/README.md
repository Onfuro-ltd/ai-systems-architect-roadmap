# Domain 23 — AI Product Design

## Learning objectives

By the end of this domain, you should be able to:

- explain the core concepts and distinctions across AI product capability design, human-AI interaction, uncertainty, trust, approvals, user control, failure UX and lifecycle.
- build or evaluate a representative implementation rather than relying on a demo;
- make architecture decisions that account for reliability, security, cost, scale and operations;
- define the evidence, evaluation and governance required before production adoption.

## Purpose

AI product design turns probabilistic capabilities into products people can understand, control and rely on.

> A good AI product does not hide uncertainty behind a polished interface. It designs the interaction so users know what the system can do, what evidence it used, what remains uncertain, and what will happen before consequential actions occur.

## Core product loop

```text
User intent
    ↓
Capability + permission boundary
    ↓
AI proposal / result
    ↓
Evidence + uncertainty
    ↓
User review / control when needed
    ↓
Action / outcome
    ↓
Verification
    ↓
Feedback + evaluation
```

## Principles

1. Design around measured capability, not demo performance.
2. Make consequential effects visible before they happen.
3. Communicate uncertainty in a form users can act on.
4. Show evidence where verification matters.
5. Preserve user control and reversible paths.
6. Increase autonomy only with evidence.
7. Design explicitly for failure and degraded operation.
8. Separate feedback from verified learning signals.
9. Measure user outcomes, not chat volume.
10. Keep model/provider details below stable product contracts.

## Takeaway

> AI product design is the discipline of turning uncertain machine capability into understandable, controllable and measurable human outcomes.
